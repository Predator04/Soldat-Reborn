# Tracerfall (formerly Soldat Reborn) — project context

**Name (#269):** the game is shown as **Tracerfall** (`GameInfo.TITLE`; window title set in `Settings._ready`). Internal identifiers deliberately keep the old name: `project.godot` `config/name` (it decides the user:// data folder — changing it orphans every player's settings, stats and replays), the Android package id `com.soldatreborn.game`, the update/release asset names `SoldatReborn.exe/.apk/.pck(.sig)`, the LAN tag and the updater URL (the GitHub repo itself is now Predator04/Tracerfall; GitHub redirects the old URL for downloads, but `tools/github/sync.py` must use the new name because redirects are not replayed for POSTs). Never "fix" those.

2D Soldat remake. Godot 4.7 (GL Compatibility renderer), GDScript, ENet multiplayer.
This directory (`game/`) is the git repo root — note the space in the parent path `"soldat reborn"`.

## Entry & boot
- `scenes/menu.tscn` is the main scene; gameplay is `scenes/main.tscn`.
- 1280×720 viewport, `canvas_items` stretch, aspect `expand`.
- Autoloads (`project.godot`): `Sfx`, `Settings`, `Net`, `GifRecorder`, `Stats`, `Music`, `MatchConfig`.

## UI design language, motion, UI scale (#272)
- **One source: `scripts/ui_theme.gd` (`UITheme`).** Palette (`COL_*`: glass panels, off-white text, warm `COL_ACCENT` ember for primary actions / section headers, cool `COL_NEON` for hover edges / focus ring / highlights), type scale (`FS_*`), fonts via `UITheme.font(kind)` (body / semi / head / caps / title / display / logo / hud — Barlow + Barlow Condensed in `assets/fonts`, OFL, license file shipped and credited), radii, and the style factories (`panel_style`, `card_style`, `hud_strip_style`, `hud_pill_style`, `style_button`, `style_option_button`, `style_checkbox`, `style_lineedit`, `make_section_header`, `make_rule`, `draw_icon` vector HUD icons, `icon_texture`). `install_global()` (Settings._ready) MERGES the theme into the engine default theme — a theme set on the root window does not reach Controls under CanvasLayers (HUD, pause) — and sets `ThemeDB.fallback_font`. New UI: use these helpers and colours, never ad-hoc Color literals or Open Sans sizes.
- **Motion: `scripts/ui_fx.gd`** (`UITheme.UIFx`). `bind_button` (called by the style helpers): hover / focus 1.03, press 0.97 about the centre, neon sweep, `Sfx.ui_hover` / `Sfx.ui`. `watch(c, dir)` / `watch_children(root)`: whenever a screen becomes visible in the tree it slides 28 px from `dir` + fades in (0.2 s). It animates only `modulate.a` and a temporary OFFSET delta (never `position` — that bakes a still-settling size into the offsets), so input works on frame one and hiding mid-way restores the layout exactly. Keep switching screens with plain `visible` toggles. `pop()` for HUD banners / toasts. **Reduce motion** (`Settings.reduce_motion`) turns all of it into instant state changes (also the menu backdrop drift / embers, logo streak, kill-feed fades).
- **UI scale** (`Settings.ui_scale`, Settings → Video, 0.85–1.3): `UITheme.apply_ui_scale(root)` on the menu scene root, the pause `_root_panel` and the HUD `_ui`; `refresh_ui_scale(tree)` applies a change live. Layout code must use the root's `size` (menu `_fit_panels`, `_centre`) rather than the viewport.
- **BACK rule (`scripts/ui_back.gd`, `UIBack` via preload).** Android BACK (`NOTIFICATION_WM_GO_BACK_REQUEST`; `quit_on_go_back` is off), Esc and `ui_cancel` all mean: close the TOP-MOST overlay first (open popup list → registered dialog → screen's own steps); only with nothing open does the screen take its "leave" path (menu sub-screen → main list, main list → quit, editor → menu (FILE > Exit), Maker play-test → EDIT, match → pause menu, replay → menu). Never quit / change scene from under a dialog. ONE dispatcher per scene handles both the notification (always `call_deferred` — the notification walks the tree and a scene change inside it errors) and the key: menu `_go_back`, map_editor `go_back` (asks `maker.back_pressed()` before leaving), pause_menu `go_back`, replay_player `_back`; each calls `UIBack.dismiss(get_tree())` first. A new overlay / dialog never handles BACK / Esc itself: `UIBack.register(control, close_callable)` (a no-op callable for a dialog that must stay, e.g. the first-launch name prompt); the topmost visible one (canvas layer, then tree order) is closed. A focused LineEdit eats the first Esc (ends editing), that's fine. Gate F `back` (`tools/back_button_test.gd`, BACK-TEST) — add any new screen / dialog to it.
- Menu: `menu_backdrop.gd` (CanvasLayer -10: shader sky + `parallax_cinematic.gd` with `center_override` drift + embers + light sweep + grade; Low = photo), `menu_logo.gd` (wordmark + tracer streak). Settings live preview: `settings_preview.gd` (one SubViewport stage, built by `settings_panel._sync_preview` only while Settings is open from the main menu, freed on hide). Gate F `ui` (`tools/ui_test.gd`); `tools/ui_capture.gd [--tour]` renders the screens.

## Graphics: cosmetic-only rule, pools, FX RNG, hit-stop (#270 / #271)
- **Visuals are cosmetic only.** No effect may touch the simulation: physics bodies / collision layers, game state, timers, `Engine.time_scale`, RPCs or the global random stream. Effects run on every peer from events the host already replicates (shots, hits, deaths, explosions) — never send an RPC for a cosmetic. Gate: F `fxpool` replays the same seeded, scripted fight with all effects on and all off and requires bit-identical player pos / vel / health / fuel / ammo and the same next `randi()`.
- **FX RNG:** cosmetic randomness comes from `Gfx.rng` (`scripts/gfx.gd`, also `Gfx.rf(a, b)`); sfx pitch / variant picks use `Sfx._rng`. The global `randf()` / `randi()` belong to gameplay (weapon spread, bot AI, spawn picks). Never call them from effects, sound or UI.
- **Pools (`scripts/gfx/fx_world.gd`, class `FxWorld`, one per match under Main, added in `match_world._build_gfx_world` before any soldier):** structure-of-arrays pools sized per quality [Low / Medium / High] at match start or on a quality change (`FxWorld.reconfigure()`): particles 0/420/1000 (per-kind caps: spark, ember, glow 40, muzzle star, smoke 60, dust, mist, blood drop, debris), gibs 0/28/72, casings 0/24/64, decals 0/96/256 (ring, oldest recycled), heat rings 0/0/6, wound spurts 0/6/16, terrain-testing blood drops 0/16/48. Drawn by four canvas items via their `draw` signal: `Decals` + `Back` (z 0, tree-ordered behind soldiers), `Add` (z 60, additive), `Heat` (z 66, `heat_haze.gdshader`, High). Never instantiate a node per effect; add a kind / pool instead. `Gfx.flash/muzzle/explosion/smoke/casing/dust/scorch` and `ImpactFx.spawn` are the entry points; deaths call `FxWorld.ensure(parent).gib(...)` (Blood slider 0 = nothing). Ray-tests use mask 1 with `hit_from_inside`.
- **Screen feel (`scripts/gfx/screen_feel.gd`, `ScreenFeel`):** shake = trauma (`ScreenFeel.shake(px)`, called by `player._shake` only for the soldier whose camera is current; explosions add by distance), applied to the local player's `cam.offset` in `_process`. Hit-stop = presentation freeze: one viewport read-back into a reused `ImageTexture` shown full-screen on CanvasLayer 126 for 50–90 ms while the match keeps simulating; slow-mo = `punch` / `smear` / `desat` uniforms on `post_cinematic.gdshader` + `Sfx.fx_duck_db`. Only the local player's kills (hud `_on_kill`) / heavy hits (hud hp watch) trigger them; `Settings.hit_stop` and Screen Shake 0 turn them off; Low has none.
- **Soldier feel (`scripts/gfx/soldier_feel.gd`):** squash-and-stretch / recoil / damage flash computed in `_draw` from replicated state into `SoldierDrawState.fx_*`; `soldier_art.gd` / `gostek.gd` compose them into the DRAWN transforms (never the node scale — the collision shape is a child). The flash is the `flash` instance uniform of the shared rim (cinematic) / `soldier_flash.gdshader` (classic, Medium+) material that `atmosphere.gd` assigns to soldiers.
- Scripts loaded by a `-s` test before autoloads exist must not reference these class_names at compile time — `load()` them lazily (see `tools/fx_test.gd`).

## HD terrain (#283)
- Cinematic look at Medium / High only (`terrain_hd.gd` static `wanted()`: `Settings.visual_style == "cinematic"`, Medium+, not headless; static `force_hd_for_tests` for gate F `terrain`, `suppress` for "before" captures — no class_name, `load()` the script to reach them). Low, the classic look and headless keep the classic polygon nodes exactly as they are.
- `match_world._build_terrain` registers every drawn polygon / platform / visible floor + walls in `_hd_items` (`{nodes, pts, vc, uvs, col, tex, cc, mod}`); `_build_gfx_world` adds `scripts/gfx/terrain_hd.gd` (Node2D "TerrainHD" under Main, z -1). Built ONCE per map, shown by hiding the registered classic nodes + `terrain_fx` (restored on a switch back): `Fill` = one ArrayMesh of every polygon in file order, `terrain_hd.gdshader` (3 material slots, per-vertex weights, height blend, fixed upper-left sun from the normal map; slot 0 is the node's CanvasTexture diffuse + normal so the 2D lights use it), `EdgeAO` (vertex colours), `Edge_<kind>` strips (grass / snow / sand / dirt / rock / metal lips on top edges as vertical skirts, roots / icicles under overhangs; outline edges come from `terrain_fx.gd` `_edges()` / `_joined_normals()`). ≤ ~10 canvas items, nothing per frame.
- Colour: each vertex keeps its CLASSIC colour (classic texture × node colour × vertex colour, graded: highlights compressed, loud saturation calmed), the material only adds detail (+ a little of its own hue, `KEEP`). The texture term is looked up at the vertex's tile UV in a 1/16 area-averaged copy (`terrain_theme.gd` `tex_small`): many classic textures are ATLASES (grass strip over rock, black + white regions) — a single mean per texture loses e.g. Airpirates' grass bands. Levels use a low percentile (high-contrast textures read darker than their mean). The fill shader reads the vertex colour in `vertex()` (fragment COLOR is pre-multiplied by TEXTURE at UV, and UV carries material weights). Non-colliding background polys (col 3 not on solid ground) are slightly greyer / flatter (kept mild: polygon art like skulls / spikes must survive); translucent polys out in the open are drawn flat.
- Mapping: `scripts/gfx/terrain_theme.gd` — `TEXTURE_MATERIAL` (every classic texture a bundled map uses → material; unknown → `guess_material` from the texture mean), `weights()` (green → grass, grey on dirt → rock, brown in a bunker → wood, white on a snow map → snow, …), `top_edge` / `under_edge`, `theme_for` (parallax theme: rock / urban / desert / snow / jungle / ruins → `parallax_cinematic.gd` `theme` silhouettes + ridge shape; "" = menu look).
- Art: `python3 tools/gen_terrain_gfx.py [names] [--sheet=F.png]` (deterministic; edit the `mat_*` / `edge_*` functions, never the images) writes `assets/terrain-hd/`: 12 materials `<m>.webp` + `<m>_n.webp` (2048 px = 1024 design texels at 2x, OpenGL normals, WebP q95 sources, imported lossy with mipmaps; the shader rebuilds normal z), `edge_<kind>.png` strips (2048×256, lossless) and `materials.json` (mean albedo per material — the shader divides by it). It patches the `.import` files (writes them if missing). High uses the 2048 px textures (VRAM ≈ 22 MB each, ≤ 6 per map ≈ 134 MB + strips); Medium makes 1024 px copies at load (`terrain_theme.gd` `material_texture`, ≈ 34 MB per map). Not VRAM-compressed on purpose: Basis / S3TC sampled ~4x slower on software GL and the Android export would carry two copies. Export size ≈ 45 MB (materials) + 4 MB (strips).
- Renders: `tools/terrain_capture.gd -- --map=<name|index> --out=DIR [--shots=N] [--zoom=Z] [--at=X,Y] [--quality=Q] [--bench] --no-perf-guard` (always pass `--no-perf-guard` on slow / software GL: main's low-FPS guard otherwise steps the quality down after 14 s) saves `<map>_<n>_before/after.png` pairs (same frame); `--bench` pans across the map with HD off then on and prints mean frame ms + draw calls.

## Vehicles (#276 / #277 / #291)
- `buggy.gd` is the base (seats, net sync, damage, wreck, respawn, bots, idle return #259); `tank.gd` and `heli.gd` extend it. Map keys `vehicle_spawns` / `tank_spawns` / `heli_spawns` / `plane_spawns` ([x, ground_y]); `tools/place_vehicles.py` writes them (`--heli` writes ONLY heli pads — a full re-run would move the buggy / tank spots of the smoothed maps, don't). All three are in group "vehicle" and expose `seat_of` (the trust guard's riding exemption).
- Net: the driver's / pilot's peer simulates (`sim_peer`, `is_sim`, `_send_state`, `apply_state`); the host owns hp / wreck / respawn / seats and drops client streams that move faster than the kind's `RELAY_MAX_SPEED` over 250 ms or leave the world (`_relay_drop`, logs `TRUST vehicle ...`). Helicopter impacts (hard landing, wall, rotor / tail strike, the crash ending a spin-out) are found by the sim peer and sent to the host (`net_vehicle_crash` → `host_crash`); the pilot's rockets use `net_vehicle_fire_seat` (host rate check `fire_seat_ready`), the MG `net_vehicle_fire`. `net_vehicle_destroy` carries `violent` (crew killed vs ejected via `_eject`).
- **Wedge recovery (#299, `buggy.gd`):** host-side `_wedge_tick` (ground kinds only — `_wedge_watch()` is false for heli / plane): a vehicle within 24 px of one spot for `WEDGE_TIME` 4 s while NOT `floor_supported()` (sim `is_on_floor()`, else a 6 px `test_move` down that hits terrain at ≤ `floor_max_angle`, or a short ray under either end / the middle of the body that does — pure terrain queries, so it works on a client-driven replica) or `|_tilt|` > 70° goes home via `net_vehicle_respawn` (`wedge_resets` counts; skipped within 24 px of its spawn). `apply_respawn` now steps any crew out first (`clear_seat_of`), and `clear_seat_of` uses `_exit_spot` (first spot beside / above the body where the soldier isn't inside terrain). Bot driver: `_bad_drop_ahead` walks the ground for the braking distance + 120 px, then flies the body on (sliding along steep faces) — landing on a face steeper than the floor angle or stopping dead = brake (`throttle = -dir`) and get out; a bail for that / the void / being stuck sets `drive_ban_t` 70 s (> idle return 60 s), which bot.gd `_think_drive` checks, so bots stop re-boarding it as driver and it drives home (don't add `bot_board_ok` to buggy.gd: bot.gd and `runtime_nav_test` read having that method as "aircraft"). Gate F `wedge` (`tools/vehicle_wedge_test.gd`: Ascent slot crewed / empty / tank, tilt, parked negatives, then an Ascent bot match); `tools/vehicle_wedge_watch.gd -- --maps=0,1,... --secs=120` sweeps bot matches for wedges / stalls.

## Networking model (critical — don't break this)
- **Host-authoritative.** Host (peer 1) spawns and mirrors every soldier, bot, projectile, and pickup. Clients send input RPCs and render what the host replicates.
- **Except human bodies:** each client simulates its own soldier's movement, jets, aim and firing (`net_state`, `net_shoot`, `net_grenade`), and every peer still simulates every shot / tracer / grenade / rocket for instant feel. But **the host decides every hit on a human** (#266, `scripts/host_hits.gd`, class `HostHits`):
  - **Routing:** every damage source calls `HostHits.damage(s, amount, killer, weapon, team[, ignore_protection, coalesce])` — never `take_damage` on a soldier directly. `route(s)`: APPLY (this peer owns the body: SP, the host's own player, bots → `take_damage`), HOST (host + remote human → `player.host_damage`), NONE (a client's own body: the host decides; the local copy only shows the impact). Bullets, melee, grenade / rocket / tank / heli splash, vehicle run-overs (`vehicle_hit_soldier`), wrecks, thrown knives and the BR ring all go through it.
  - **Ledger:** the host's copy's `health` IS the authority for a remote human. `host_damage` mirrors `take_damage` (spawn protection = `TrustGuard.protected()`: 3 s + the owner's round trip, ends when the host sees it attack; vest halving), then sends the owner `net_hit(hp_after, amount, killer, weapon, team)` (absolute health; amount 0 = a correction; per-frame sources are batched to ≤ 10/s). At 0 the host declares the death (`_host_kill` → `_fanout("net_die")` + `_die()`, credit through `kill_credit_ok`). Heals the host knows: medikits (`_apply_kit_local` on its copy), round reset (`trust_amnesty`), Rambo regen (`host_heal` in `_tick_rambo`). Clients now only report self-inflicted deaths (kill line, hazards, gestures, a grenade in hand); the client-side BR ring damage is gone.
  - **Lag compensation:** the host records ~0.65 s of hitbox history for each remote human (`HostHits.register`, `pos_hist` in `_physics_replica`, `hitbox_at` interpolates). Relayed `net_state` carries the host's clock (`host_ms`); a shot carries `view_ms` (`HostHits.view_now()`: the host moment the shooter's screen showed) and the host rewinds that shot's hits on remote humans by `now - view_ms` (`rewind_from_view`: capped at the measured round trip + 150 ms and `REWIND_MAX_MS` 400 — 250 ms players with jitter and stalls need the room). Bullets test one rewound box grown 3 px (`bullet._rewound_hit`; remote humans are excluded from the bullet's physics ray on the host); melee and client-projectile splash use `HostHits.pos_at`. A soldier in a vehicle seat is recorded at its vehicle copy's seat (`_vehicle_seat`, `buggy._seat_world`; seated replicas don't smooth toward their own — silent — state stream), and a vehicle carrying a remote human is rewound with it (`buggy._record_hist` / `pos_at` / `segment_t_at` capsule test; excluded from the ray like the crew), else its hull — where the host has it now — stops rounds that met the crew on the shooter's screen. Relayed (non-predicted) vehicle guns — the shooter only sees the round once the host relays it — use no rewind and the bare box (`buggy.apply_fire` sets `rewind_override = 0`). Round trips come from `match_net` probes (`net_rtt_probe` / `net_rtt_echo` on Main, 2 Hz, also over the relay; capped near ENet's RTT); the probe's stamp also feeds `note_view` (a soldier in a seat sends no state). Bots and the host's own player keep the old rules (current position; the host player's `lag_ms` path).
  - **Shot checks** (`player._host_shot_check`, before the shot is relayed): pellet count + unit directions, muzzle within 80 px of where the owner could have been at the shot's own game-clock moment (`TrustGuard.note_track` keeps ~1.5 s of the state stream by its `gstamp`; `origin_off`: the samples either side of that moment, each give or take what the body could cover in between; with no sample near it yet the shot is held until there is; so a shot the network held back is checked against its own moment; right after a spawn / round reset / seat change — `placed_recently` — an off shot is refused quietly instead of flagged), a muzzle poking through a wall starts the host's copy at the wall, aim: on the arc between the streamed aims either side of the shot's own moment (`aims_around(stamp)`) when both are in, else vs the last aim (`aim_ok_now`; a flick, or a shot before any aim sample, is held — `hold`, its hits parked — until the sample after its moment arrives — ≤ `AIM_HOLD_MS` 800, or `STREAM_WAIT_MS` 5000 while the owner's stream hasn't reached that moment — and settles it on that arc; only a pair of the owner's own samples either side of a shot can refuse / flag it, an unverifiable one stands (`aim_unverified`)); only shots > `AIM_FLAG_RAD` beyond the arc are flagged; melee swings are never refused on aim, only counted `melee_aim_off`), magazine (`take_round`; refilled by a reload the host saw run ≥ 60 % on the owner's game clock — the first state after it ends it — or by a pause in firing that long, pickups `host_note_pickup`, GG rung changes, amnesty), fire rate from the shot's game-clock `stamp` (`stamp_check`: spacing ≥ the weapon's rate, and the client clock may not run ahead of the host's — `clock_note`, learned per connection from the 30 Hz state stream; replaces #243's arrival gap, which dropped honest shots bunched by the network). Grenades: count + spacing by the thrower's game clock (`take_grenade(stamp)`; `net_grenade` carries one), hand position, speed, fuse. Client rockets: the host flies a "ghost" of the same flight and refuses an explosion off that path (`rocket._ghost_*`: the whole path is kept; a report may run ahead of the ghost by what the shooter's own reports account for, ≤ 0.6 s); client grenades: reported flight must be reachable (reports come 0.2 s then 1/20 s apart in the thrower's time, however bunched) and not cross a wall (`grenade._check_flight`), else the blast only shows (`harmless`, frags too). M2 / vehicle guns / heli rockets (`match_vehicles._gun_ok`): muzzle on the gun (`_gun_reach`: the kind's `FIRE_REACH` + the vehicle's speed × (0.35 s + the shooter's round trip), its copy trails the driver's), rate by the shooter's game-clock `stamp` (`net_vehicle_fire` / `net_vehicle_fire_seat` / `net_m2_fire` carry one; token bucket without).
  - **Also checked** (`trust_guard.gd`, one guard per remote human on the host): reported health vs the ledger over the last round trip (corrections; `TRUST hp: … host hits ignored` once a client keeps ignoring them), jet fuel shadow (drains while the client reports its jets on, refills generously; `TRUST fuel` + clamp of the relayed fuel), impossible speed / out of world, kill credit.
  - **Escalation:** refusals are counted in `HostHits.stats` (`refused_<kind>`, also `hits`, `damage`, `deaths`, `rewind_*`, `muzzle_in_wall`, `aim_held`, …; `--hosthits-log` prints a `HOSTHITS` summary every 5 s plus per-hit `HOSTHIT` / `HOSTSHOT` / `HOSTRECV` / shooter `PREDHIT` lines) and logged `TRUST <kind>: …` (rate-limited). 8 refused shots / 2 fuel violations / 2 movement violations in one life = host-side forced death + strike; 3 strikes in 5 min = kick. Network-bunched shots are refused quietly, never flagged.
  - **Rules:** any new damage path → `HostHits.damage`; any new attack path → `TrustGuard.note_activity`; any change to RPC arguments / meaning → bump `GameInfo.NET_PROTOCOL` (`game_info.gd`; the join handshake sends `GameInfo.net_version()` = "<version>+net<N>", mismatches get "Version mismatch: host 1.37.0 (online protocol 2), you …"). Gate: F `hosthits` / `hostcheat` (`tools/hosthits_test.gd`: real dedicated servers, `tools/udp_lag_proxy.py` delay / jitter / `--loss-pct` / `--spike-every --spike-ms` stalls, `scripts/smoke_duel.gd` scripted `--smoke-role=victim|shooter [--smoke-weapon=… --smoke-move=strafe|jet|stand|drive --smoke-cheat=…]` clients; `hosthits` = the `SCENARIOS` table — AK / Spas / knife / LAW / M79 / grenades / buggy gun, strafing / jetting / driving victims, 50–250 ms with loss and stalls, a join after a round end + map change — each must show zero refusals, agree with the shooter's own screen and tell the victim exactly what the host applied; `--scenarios=a,b --parallel=N` runs a subset; host test hooks `--smoke-medic=TAG` (+ grenade kits), `--smoke-round-secs=N`), C net `trust` (godmode now expects `TRUST hp`), and every netcase fails on a `TRUST` line from an honest client.

- Overhangs (#297): a ledge-detour climb (step out past a platform's lip to `a`, jet up to the air point `bb` beside it, step on) is linked straight `p -> bb` only when that line is clear AND a soldier fits straight up from `p` to `bb`'s height (`_rise_clear`); a `p` UNDER the platform gets `p -> a -> bb` instead (`a` = a step-out node, deduped like the air points) — the straight link ran through / along the platform body and bots following it jetted into its underside again and again. Runtime builder only: `tools/build_nav.py` still links `p -> bb` (the baked classic graphs were left as they are). Bot side (`bot.gd`, `_roof_within(x, h)` = static terrain within h px over the head): in `_nav_step` a climb waypoint up and sideways with terrain right overhead and an open column over the waypoint = walk out from under first (no jump / jets, `_under_roof`, and the link-line tracking is skipped for that waypoint, `_off_line_wp`); a waypoint straight over the roof above us = no jets + one replan (1 s cooldown); the not-navigating "target above" jump / jet doesn't fire under a roof; and a navigating bot standing still in `_refuel_wait` is not "stuck" (`wants_travel`) — the ~3 s refuel before a tall climb outlasted `PROGRESS_WINDOW`, so the escape fired mid-refuel and jumped + jetted off in a random direction (under a platform: into its underside). `rtnav` `maker_overhang`: flat ground, a float island 420 px up (red flag) + a slab 340 px up — zero climb links may start under them (ray from the link start up to its top), no bot may hit an underside 3+ times, a blue attacker must make it up to the island (on it or beside its lip at its height) within 75 s (13–55 s typically: red defends up there).
- DOM points (#296): bots used to stand on a contested point's exact centre, inside the enemy — shots start at the muzzle, past a body that close, so nobody got hit and the match froze. `bot._dom_hold_dir` (only DOM, goal label "capture", on the floor, visible enemy within 46 px): back away from it (by team when exactly on top of each other) but stay within `DOM_HOLD_X` 32 px of the point (capture radius 44); hold between 46 and 60 px. Maker basins merging with the ground under them were NOT the cause (same collision, same raster nodes; `rtnav` `maker_basin` checks both on Magma Crown with the basins merged, then plays DOM 40 s: no blue + red bot within 12 px of each other on a point for 6 s, kills > 0).
- Soldiers are on physics layer bit 8 and don't collide with each other; anything that must hit soldiers masks bit 8.
- Soak test flags: `--mode=N`, `--trace=<goal label>`, `--trace-name=Blue_Bot_2`, `--log-falls`.

## Gotchas
- GDScript uses TAB indentation — do not convert to spaces.
- Version string is in `project.godot` (`config/version`); bump it for releases together with `export_presets.cfg` (Android `version/name` + `version/code` = MAJOR*10000+MINOR*100+PATCH, Windows `file_version`/`product_version` = X.Y.Z.0) and the top `CHANGELOG.md` heading — the gate checks they agree.
- Release gate: `tools/release_gate.sh` (full, ~20 min: static, boots, nav, MP smokes incl. per-mode `m3 m7 m9` + LAN discovery + a two-client autopilot soak, all 10 modes with the autopilot, rules, feature/editor tests, all-map CTF sweep) or `--quick` (CI). Must end `GATE PASSED`; logs in `build/gate/`. Every Godot launch in the gate starts from default settings/controls (the user's files are backed up and restored), so results don't depend on this machine's saved settings. Piecewise runs (for time-limited shells): `--out build/gateN --only "A B"`, then `--keep` with `--only N`, `--only C --net "..."`, `--only D --modes "..."`, `--only R`, `--only F --ftests "features editor grenade training course" / "weapons" / "fire labels kits sound" / "radio"`, `--only E --sweep 0:24 …75:101`, `--only E`, `--final`. The error regex also fails on engine messages ("Lambda capture … freed", "while flushing queries").
- **Release gate on a shared / loaded box (#293)** — several gates often run at once on the 2-core dev box; the gate is built so that never causes a false FAIL:
  - *Isolation:* each run has its own user-data dir (`XDG_DATA_HOME=$OUT/.userdata-<pid>-<time>`, fresh `settings.cfg` / `controls.cfg` per launch, deleted at exit, `GATE_KEEP_USERDATA=1` keeps it — parallel runs used to share `~/.local/share/godot/app_userdata/Soldat Reborn` and delete / list each other's replays) and its own LAN discovery port (`TRACERFALL_LAN_PORT`, read by `Net.lan_discovery_port`; default 23074 for players — a second listener on one port can't bind, and Quick Play joined another gate's server). Game / query / master ports come from `freeport udp|tcp` (bind test), never `RANDOM`. The machine's own user files are not touched. Never write a test that depends on files outside `user://` of its own run.
  - *Master server:* `SERVER_DIR` = the master-server checkout (or the dir holding `master-server/`); default `../server/master-server`, and from a git worktree the same path beside the main checkout. A missing binary is one explicit FAIL per case.
  - *Load factor:* `LOAD = (1-min loadavg + 1) / CPUs`, clamped [1, 4], measured at start and re-read per step (never below the start). `T N` scales every `timeout` and wait (`wait_log FILE REGEX SECS`, `wait_ready LOG` = "listening on port" then the dedicated server's `Dedicated match ready` line — clients start on that line, not after a fixed sleep). Godot launches get `GATE_LOAD` (recomputed per launch by `.godot_fresh.sh`): `net.gd _smoke_secs` stretches smoke-client windows by it, `tools/selfcheck.py` / `tools/mp_soak.sh` their waits, and tests' own wall-clock deadlines use `tools/gate_load.gd` (`GL.wait_ms(ms)`). Only waits / deadlines scale — never a measured limit.
  - *Measuring time in a test:* never assert on raw wall-clock gaps. `tools/gate_load.gd` `stamp()` / `own_ms()` (wall minus this thread's run-queue wait, `/proc/self/schedstat`) / `cpu_ms()` (on-CPU). F `perf` gates on main-thread CPU per frame (avg < 6 ms, worst < 80 ms; same seeded fight every run; a calibration workload only loosens the limits on a slower machine, ≤ 2x) — seen 4.9-5.4 ms quiet or at load 9 while wall averages ran 6-58 ms. **Regression self-check:** `PERF_INJECT_MS=10 tools/release_gate.sh --only F --ftests perf` (or `--inject-ms=10`) burns 10 ms of main-thread CPU per frame and must FAIL. F `rtnav` stall = `main.nav_adopt_ms` capped by that frame's own time (< 400 ms) + no frame over 2 s own time during the build; its build deadline scales with the load.
  - *Event order, not sleeps:* C `two` / `fill` start the second client once the host logs `FILL humans=1`; F `features` pushes the steps after a held step 9 back by the wait; F `radio` stages the flag grab (a bot put on an enemy flag) after 60 s without a natural one; C `two` counts every player body seen during the window; F `vart` resets parked vehicles at each state and ignores in-flight projectiles / the bot's respawn in the node count; F `grenade` expects the fuse of the grenade actually thrown (cluster bonus boxes); F `rtnav` checks "graph present before the runtime build" on the match's FIRST frame.
  - To run your own gate while editing `tools/release_gate.sh`, run a copy (`cp tools/release_gate.sh build/rg.sh; bash build/rg.sh ...`): bash reads a script as it runs, so editing the running file corrupts the run.
- Host broadcasts from `main.gd` go through `bcast(method, args, local)` (reaches only peers whose Main exists). Dead / disconnected soldiers linger 1.5 s as an inert husk (`player._become_husk`) so in-flight packets still find the node.
- Host → client RPCs from bots/projectiles go only to acked peers (`ready_peer_ids()`, `_bcast`, `_net_send`); a plain `rpc()` reaches peers still loading and spams "Node not found".
- MP respawns are scheduled by `main._schedule_peer_respawn`; objective events go through `_objective_event` (never the `kill` signal).
- Path has a space (`soldat reborn/game`) — always quote it in shell commands.
- Movement course (#262 / #301): geometry + gate constants in `scripts/movement_course.gd` (re-run `tools/make_movement_course.gd`, `build_nav.py movement_course`, `make_thumbs.py`, `map_audit.py` after a change), gates in `training.gd`. Calibrate gates against a HUMAN timing window, not one perfect frame: gate F `course` sweeps the prone-drop press time through the real input path (`Input.action_press`) and asserts each outcome + message. The training overlay runs before the soldier's physics tick, so it can hold back a press by marking it seen (`x_prev`) — that's how the drop buffers X pressed just before the edge (course-only; player.gd controls stay as in multiplayer). In player.gd, holding jump stands you up from prone only on the ground; in the air only a fresh jump press does.
- Remote bodies are smoothed: set replica positions through `net_apply_pos(pos, vel)` (player.gd / bot.gd), not `position =`. Nav JSON `air` = mid-air waypoints; never use them as patrol/roam targets.
- Builds: `tools/build_release.sh [win|android|all]` → build/SoldatReborn.exe + signed .apk (stub SDK + uber-apk-signer; keystore lives in ../keys, outside the repo).
- After changing map JSON (regen / overrides) also re-run `python3 tools/build_nav.py` and `python3 tools/make_thumbs.py` (menu previews in assets/map_thumbs).
- GitHub tracking: every bug / feature gets an issue first (bug report / feature templates, `bug`|`enhancement` + `area: …` labels), the fixing commit says `Fixes #N`, the CHANGELOG line cites `(#N)`, releases carry the exe + apk (`python tools/github/sync.py release`). Work done without network access goes into `tools/github/backlog_*.json` and is filed + closed with `sync.py backlog`.
