# Tracerfall (formerly Soldat Reborn) — project context

**Name (#269):** the game is shown as **Tracerfall** (`GameInfo.TITLE`; window title set in `Settings._ready`). Internal identifiers deliberately keep the old name: `project.godot` `config/name` (it decides the user:// data folder — changing it orphans every player's settings, stats and replays), the Android package id `com.soldatreborn.game`, the update/release asset names `SoldatReborn.exe/.apk/.pck(.sig)`, the LAN tag and the repo name/URL. Never "fix" those.

2D Soldat remake. Godot 4.7 (GL Compatibility renderer), GDScript, ENet multiplayer.
This directory (`game/`) is the git repo root — note the space in the parent path `"soldat reborn"`.

## Entry & boot
- `scenes/menu.tscn` is the main scene; gameplay is `scenes/main.tscn`.
- 1280×720 viewport, `canvas_items` stretch, aspect `expand`.
- Autoloads (`project.godot`): `Sfx`, `Settings`, `Net`, `GifRecorder`, `Stats`, `Music`, `MatchConfig`.

## UI design language, motion, UI scale (#272)
- **One source: `scripts/ui_theme.gd` (`UITheme`).** Palette (`COL_*`: glass panels, off-white text, warm `COL_ACCENT` ember for primary actions / section headers, cool `COL_NEON` for hover edges / focus ring / highlights), type scale (`FS_*`), fonts via `UITheme.font(kind)` (body / semi / head / caps / title / display / logo / hud — Barlow + Barlow Condensed in `assets/fonts`, OFL, license file shipped and credited), radii, and the style factories (`panel_style`, `card_style`, `hud_strip_style`, `hud_pill_style`, `style_button`, `style_option_button`, `style_checkbox`, `style_lineedit`, `make_section_header`, `make_rule`, `draw_icon` vector HUD icons, `icon_texture`). `install_global()` (Settings._ready) MERGES the theme into the engine default theme — a theme set on the root window does not reach Controls under CanvasLayers (HUD, pause) — and sets `ThemeDB.fallback_font`. New UI: use these helpers and colours, never ad-hoc Color literals or Open Sans sizes.
- **Motion: `scripts/ui_fx.gd`** (`UITheme.UIFx`). `bind_button` (called by the style helpers): hover / focus 1.03, press 0.97 about the centre, neon sweep, `Sfx.ui_hover` / `Sfx.ui`. `watch(c, dir)` / `watch_children(root)`: whenever a screen becomes visible in the tree it slides 28 px from `dir` + fades in (0.2 s). It animates only `modulate.a` and a temporary OFFSET delta (never `position` — that bakes a still-settling size into the offsets), so input works on frame one and hiding mid-way restores the layout exactly. Keep switching screens with plain `visible` toggles. `pop()` for HUD banners / toasts. **Reduce motion** (`Settings.reduce_motion`) turns all of it into instant state changes (also the menu backdrop drift / embers, logo streak, kill-feed fades).
- **UI scale** (`Settings.ui_scale`, Settings → Video, 0.85–1.3): `UITheme.apply_ui_scale(root)` on the menu scene root, the pause `_root_panel` and the HUD `_ui`; `refresh_ui_scale(tree)` applies a change live. Layout code must use the root's `size` (menu `_fit_panels`, `_centre`) rather than the viewport.
- Menu: `menu_backdrop.gd` (CanvasLayer -10: shader sky + `parallax_cinematic.gd` with `center_override` drift + embers + light sweep + grade; Low = photo), `menu_logo.gd` (wordmark + tracer streak). Settings live preview: `settings_preview.gd` (one SubViewport stage, built by `settings_panel._sync_preview` only while Settings is open from the main menu, freed on hide). Gate F `ui` (`tools/ui_test.gd`); `tools/ui_capture.gd [--tour]` renders the screens.

## Graphics: cosmetic-only rule, pools, FX RNG, hit-stop (#270 / #271)
- **Visuals are cosmetic only.** No effect may touch the simulation: physics bodies / collision layers, game state, timers, `Engine.time_scale`, RPCs or the global random stream. Effects run on every peer from events the host already replicates (shots, hits, deaths, explosions) — never send an RPC for a cosmetic. Gate: F `fxpool` replays the same seeded, scripted fight with all effects on and all off and requires bit-identical player pos / vel / health / fuel / ammo and the same next `randi()`.
- **FX RNG:** cosmetic randomness comes from `Gfx.rng` (`scripts/gfx.gd`, also `Gfx.rf(a, b)`); sfx pitch / variant picks use `Sfx._rng`. The global `randf()` / `randi()` belong to gameplay (weapon spread, bot AI, spawn picks). Never call them from effects, sound or UI.
- **Pools (`scripts/gfx/fx_world.gd`, class `FxWorld`, one per match under Main, added in `match_world._build_gfx_world` before any soldier):** structure-of-arrays pools sized per quality [Low / Medium / High] at match start or on a quality change (`FxWorld.reconfigure()`): particles 0/420/1000 (per-kind caps: spark, ember, glow 40, muzzle star, smoke 60, dust, mist, blood drop, debris), gibs 0/28/72, casings 0/24/64, decals 0/96/256 (ring, oldest recycled), heat rings 0/0/6, wound spurts 0/6/16, terrain-testing blood drops 0/16/48. Drawn by four canvas items via their `draw` signal: `Decals` + `Back` (z 0, tree-ordered behind soldiers), `Add` (z 60, additive), `Heat` (z 66, `heat_haze.gdshader`, High). Never instantiate a node per effect; add a kind / pool instead. `Gfx.flash/muzzle/explosion/smoke/casing/dust/scorch` and `ImpactFx.spawn` are the entry points; deaths call `FxWorld.ensure(parent).gib(...)` (Blood slider 0 = nothing). Ray-tests use mask 1 with `hit_from_inside`.
- **Screen feel (`scripts/gfx/screen_feel.gd`, `ScreenFeel`):** shake = trauma (`ScreenFeel.shake(px)`, called by `player._shake` only for the soldier whose camera is current; explosions add by distance), applied to the local player's `cam.offset` in `_process`. Hit-stop = presentation freeze: one viewport read-back into a reused `ImageTexture` shown full-screen on CanvasLayer 126 for 50–90 ms while the match keeps simulating; slow-mo = `punch` / `smear` / `desat` uniforms on `post_cinematic.gdshader` + `Sfx.fx_duck_db`. Only the local player's kills (hud `_on_kill`) / heavy hits (hud hp watch) trigger them; `Settings.hit_stop` and Screen Shake 0 turn them off; Low has none.
- **Soldier feel (`scripts/gfx/soldier_feel.gd`):** squash-and-stretch / recoil / damage flash computed in `_draw` from replicated state into `SoldierDrawState.fx_*`; `soldier_art.gd` / `gostek.gd` compose them into the DRAWN transforms (never the node scale — the collision shape is a child). The flash is the `flash` instance uniform of the shared rim (cinematic) / `soldier_flash.gdshader` (classic, Medium+) material that `atmosphere.gd` assigns to soldiers.
- Scripts loaded by a `-s` test before autoloads exist must not reference these class_names at compile time — `load()` them lazily (see `tools/fx_test.gd`).

Animations, joint positions, weapon anchors and hit boxes are untouched. ## HD terrain (#283)
- Cinematic look at Medium / High only (`terrain_hd.gd` static `wanted()`: `Settings.visual_style == "cinematic"`, Medium+, not headless; static `force_hd_for_tests` for gate F `terrain`, `suppress` for "before" captures — no class_name, `load()` the script to reach them). Low, the classic look and headless keep the classic polygon nodes exactly as they are.
- `match_world._build_terrain` registers every drawn polygon / platform / visible floor + walls in `_hd_items` (`{nodes, pts, vc, uvs, col, tex, cc, mod}`); `_build_gfx_world` adds `scripts/gfx/terrain_hd.gd` (Node2D "TerrainHD" under Main, z -1). Built ONCE per map, shown by hiding the registered classic nodes + `terrain_fx` (restored on a switch back): `Fill` = one ArrayMesh of every polygon in file order, `terrain_hd.gdshader` (3 material slots, per-vertex weights, height blend, fixed upper-left sun from the normal map; slot 0 is the node's CanvasTexture diffuse + normal so the 2D lights use it), `EdgeAO` (vertex colours), `Edge_<kind>` strips (grass / snow / sand / dirt / rock / metal lips on top edges as vertical skirts, roots / icicles under overhangs; outline edges come from `terrain_fx.gd` `_edges()` / `_joined_normals()`). ≤ ~10 canvas items, nothing per frame.
- Colour: each vertex keeps its CLASSIC colour (classic texture × node colour × vertex colour, graded: highlights compressed, loud saturation calmed), the material only adds detail (+ a little of its own hue, `KEEP`). The texture term is looked up at the vertex's tile UV in a 1/16 area-averaged copy (`terrain_theme.gd` `tex_small`): many classic textures are ATLASES (grass strip over rock, black + white regions) — a single mean per texture loses e.g. Airpirates' grass bands. Levels use a low percentile (high-contrast textures read darker than their mean). The fill shader reads the vertex colour in `vertex()` (fragment COLOR is pre-multiplied by TEXTURE at UV, and UV carries material weights). Non-colliding background polys (col 3 not on solid ground) are slightly greyer / flatter (kept mild: polygon art like skulls / spikes must survive); translucent polys out in the open are drawn flat.
- Mapping: `scripts/gfx/terrain_theme.gd` — `TEXTURE_MATERIAL` (every classic texture a bundled map uses → material; unknown → `guess_material` from the texture mean), `weights()` (green → grass, grey on dirt → rock, brown in a bunker → wood, white on a snow map → snow, …), `top_edge` / `under_edge`, `theme_for` (parallax theme: rock / urban / desert / snow / jungle / ruins → `parallax_cinematic.gd` `theme` silhouettes + ridge shape; "" = menu look).
- Art: `python3 tools/gen_terrain_gfx.py [names] [--sheet=F.png]` (deterministic; edit the `mat_*` / `edge_*` functions, never the images) writes `assets/terrain-hd/`: 12 materials `<m>.webp` + `<m>_n.webp` (2048 px = 1024 design texels at 2x, OpenGL normals, WebP q95 sources, imported lossy with mipmaps; the shader rebuilds normal z), `edge_<kind>.png` strips (2048×256, lossless) and `materials.json` (mean albedo per material — the shader divides by it). It patches the `.import` files (writes them if missing). High uses the 2048 px textures (VRAM ≈ 22 MB each, ≤ 6 per map ≈ 134 MB + strips); Medium makes 1024 px copies at load (`terrain_theme.gd` `material_texture`, ≈ 34 MB per map). Not VRAM-compressed on purpose: Basis / S3TC sampled ~4x slower on software GL and the Android export would carry two copies. Export size ≈ 45 MB (materials) + 4 MB (strips).
- Renders: `tools/terrain_capture.gd -- --map=<name|index> --out=DIR [--shots=N] [--zoom=Z] [--at=X,Y] [--quality=Q] [--bench] --no-perf-guard` (always pass `--no-perf-guard` on slow / software GL: main's low-FPS guard otherwise steps the quality down after 14 s) saves `<map>_<n>_before/after.png` pairs (same frame); `--bench` pans across the map with HD off then on and prints mean frame ms + draw calls.

## Vehicles (#276 / #277)
- `buggy.gd` is the base (seats, net sync, damage, wreck, respawn, bots, idle return #259); `tank.gd` and `heli.gd` extend it. Map keys `vehicle_spawns` / `tank_spawns` / `heli_spawns` ([x, ground_y]); `tools/place_vehicles.py` writes them (`--heli` writes ONLY heli pads — a full re-run would move the buggy / tank spots of the smoothed maps, don't). All three are in group "vehicle" and expose `seat_of` (the trust guard's riding exemption).
- Net: the driver's / pilot's peer simulates (`sim_peer`, `is_sim`, `_send_state`, `apply_state`); the host owns hp / wreck / respawn / seats and drops client streams that move faster than the kind's `RELAY_MAX_SPEED` over 250 ms or leave the world (`_relay_drop`, logs `TRUST vehicle ...`). Helicopter impacts (hard landing, wall, rotor / tail strike, the crash ending a spin-out) are found by the sim peer and sent to the host (`net_vehicle_crash` → `host_crash`); the pilot's rockets use `net_vehicle_fire_seat` (host rate check `fire_seat_ready`), the MG `net_vehicle_fire`. `net_vehicle_destroy` carries `violent` (crew killed vs ejected via `_eject`).
- Helicopter numbers: HP 420, bullets x0.5, explosives x1.5 (splash), climb 300 / sink 55 / descend 380 px/s, 470 px/s sideways, rotor spin-up 1 s (lift at 85 %), ceiling y 130, hard landing > 380 px/s, rockets 2 per 3 s (85 dmg, 115 blast, ±0.42 rad of the nose), respawn 35 s, spin-out ≤ 3 s. Bot pilot = `heli._bot_pilot` (host only).
- Art (cosmetic only): `scripts/gfx/vehicle_art.gd` (shared drawing kit), each vehicle's `_fx_tick` (`_process`) emits pooled FX (`FxWorld.wheel_dust / vehicle_sparks / vehicle_burn / vehicle_wreck / rotor_wash`) and keeps lamps via `Atmosphere.light_keep`; `_draw_hull / _draw_wreck / _draw_gun / _draw_overlay` per kind. Rim light is painted per edge (the shader can't see polygon edges). The heli's cabin interior is a child canvas item behind the crew. Gate: F `vart`, `heli`, `tank`, `vehicles`, `vreset`; C `drive`, `heli`. `tools/vehicle_stage.gd` = staged renders.

## Level sharing (#288)
- **Game.** `scripts/levels_panel.gd` = the LEVELS browser (full-rect Control; menu `_open_levels(tab)` / `_levels_panel`, in `_go_back`'s panel list; the editor opens it as an overlay with `in_menu = false`). Tabs hot / new / plays / likes / bookmarks / search + the course-code box (`open_code`); cards are Buttons (`MOUSE_FILTER_PASS` so touch drags still scroll) with a `level_thumb.gd` outline; the detail panel has PLAY (`play_selected`: downloads → `user://levels/<id>/<title>.json` cache → `LevelsApi.report_play` on the tree root (survives the scene change) → `Settings.custom_map_path` + `game_mode` → `play_hook` = menu `_go_to_match`), HOST ONLINE (`host_requested` → menu `host_level(path, title)` adds the file to the Host screen's custom list and opens Host — the normal custom-map hosting path; from the editor it goes through `LevelsPanel.pending_host` and the menu picks it up in `_ready`), LIKE (optimistic, settles on the reply), BOOKMARK (`Settings.level_bookmarks`, settings.cfg `[levels]`, ≤ 100, meta cached so the tab works offline). Hidden = cards freed (`_release`), so the node count stays flat.
- `scripts/levels_api.gd` — one HTTPRequest per kind (list / get / code / like / upload), 12 s timeouts, callbacks `(ok, data, err)` with friendly errors (`offline_text()`, 429, 404, pre-#288 master). Base URL = `Settings.master_url`. Likes / plays are counted under `Settings.level_pid()` (sha256 of `"levels:" + profile_id`, so it can't be tied to the leaderboard hash). No RPCs.

## Maker mode (#286)
- The map editor (`scenes/map_editor.tscn`, `map_editor.gd`) opens in **Maker mode**: `scripts/maker/maker_mode.gd` (child node `_maker`; UI on its own CanvasLayer, input via `handle_input`, world drawn by `draw_world` into the editor canvas). The classic tools are the **ADVANCED** mode of the same editor and the same `_map` (`_set_maker(on)`; Advanced "Maker" button goes back). Undo / redo = the editor's whole-map snapshots (`_checkpoint`, `_undo_step`), so every Maker edit is undoable.
- **Source vs playable map.** The editor's `_map` is the SOURCE: entities live in the normal map keys (spawns, `team_spawns` {1, 2}, flags, pickups, vehicles, `ladders`, `scenery`) and terrain / spikes / lava / pads / props are pieces in `_map["maker"]` (`{v, theme, grid, w, h, bottom, pieces: [{t, x, y, w, h, r, f}]}` — `t` = palette id, x/y = centre, r = quarter turns, f = mirror; fixed key order + float/int types so JSON round trips compare equal). `scripts/maker/maker_build.gd` `compile()` produces the PLAYABLE map every reader understands; `decompile()` strips exactly what compile added (the maker block records `base_polys` / `base_coll` / `base_scenery` / `ffa_fill` / `anchor` / `auto`). Saving, play-testing (also the Advanced path) and PLAY always write `compile(_map)`; loading runs `decompile`. A map without a maker block passes through unchanged.
- **compile():** solid pieces of one collision class (0 solid, 2 players-only: ledges / bridges (wood tint separate), 1 bullets-only: bullet wall) are unioned (`Geometry2D.merge_polygons`; a merge that would leave a hole is skipped, those pieces stay separate), filleted (<= ~4 px, `FILLET`), decomposed into convex `collision` pieces and drawn as `polys` clipped to a 160 px grid with per-vertex colours by depth below the surface (`maker_themes.gd` top lip -> body -> deep) + tile UVs on the theme's light classic texture — that texture picks the HD material family (`terrain_theme.gd`), the colours pick grass / dirt / snow per vertex and the painted edges. Lava adds a U-shaped rock basin (merges with neighbours), spikes / lava -> `hazards`, pads -> `jump_pads`, props (crates, sandbags, barrel) -> a `prop: true` collision box (no painted edge: `match_world` skips it) + a scenery sprite at z 0. Theme -> `terrain_texture`, `sky`, `weather`; maker size / bottom -> `world` (bottomless: `kill_y = h - 100`). No FFA spawns -> team spawns are copied to `bot_spawns`; no platforms -> one 8 px anchor platform at (-200, -200) (outside the world, unreachable) because older readers (map library share check) treat a map without platforms as empty; missing INF / HTF flag, Rambo bow, CTF flags, DOM points are placed on the terrain (`_auto_objectives`) so every mode works on a bottomless map. `_mk_outlines` = editor preview only (map_io never writes it).
- Catalog + vector art: `scripts/maker/maker_pieces.gd` (tabs, kinds shape / hazard / pad / prop / entity / ladder / scenery, default sizes, rotate / flip / resize rules, thumbnails = the same drawing the editor view uses). `validate(compiled, mode)` returns friendly `{lvl, msg, at}` problems (errors block PLAY / SAVE: nothing to stand on, buried / out-of-world / in-a-kill-zone entities, missing team spawns in team modes, missing CTF flags in CTF).
- **Hazards in the game:** `scripts/match_hazards.gd` (Main helper `_hazards`, built after the gfx world, ticked in `main._process` next to the kill line) — applied by each soldier's AUTHORITY like the kill line: kill zones = `take_damage(9999, self, "Spikes" / "Lava")`, pads set the owner's `velocity.y = -power` (1150 / 1600, cooldown 0.4 s; clears the #262 jump cut / sustain). Look: `scripts/maker/hazard_visual.gd` + `hazard_art.gd` (shared with the editor + thumbnails; cosmetic). Bots: `main.has_hazards()` / `hazard_at()` in `bot._pit_ahead`, `hazard_safe_goal()` in `bot._set_goal`. map_io reads / writes `hazards` [{kind, rect: [x, y, w, h], dir}], `jump_pads` [{pos, power}], `maker`, poly `uvs`, `weather`, collision `prop`. `tools/map_audit.py` treats kill zones as pits and flags entities in them; `python3 tools/map_audit.py <file.json>` audits one map (e.g. a saved Maker map).
- **PLAY / EDIT:** `maker_mode.play()` validates, saves `user://maps/_playtest.json`, stores the editor state (source map, undo / redo, camera, tab, test mode, previous `Settings.game_mode`, spawn = world point under the view centre) in `Net.maker_return`, starts main.tscn. Main: `_maker_spawn_override` puts the first spawn on the ground under that point; `_build_maker_bar` = EDIT button (top centre); `maker_edit()` (button, F5, pause menu Quit) clears `custom_map_path` and returns to the editor, whose `_ready` calls `restore_session`. The menu clears `Net.maker_return`.
- Touch: real touches are handled as touches (emulated mouse events from touch are ignored in the world; the palette cards use the emulated mouse): one finger on a piece drags it, on empty space pans (or box-selects with the SELECT toggle), two fingers pinch / pan, long press = context menu. Gate F `maker` (`tools/maker_test.gd`); `tools/maker_capture.gd -- --out=DIR [--theme=T] [--themes] [--no-play] [--locale=de] --no-perf-guard` renders the editor / a match / every theme (xvfb).

## Networking model (critical — don't break this)
- **Host-authoritative.** Host (peer 1) spawns and mirrors every soldier, bot, projectile, and pickup. Clients send input RPCs and render what the host replicates.
- **Except human bodies:** each client simulates its own soldier — movement, the damage it takes, and its own death report (`net_state`, `take_damage` on the owner, `net_die`). The host checks that story in `trust_guard.gd` (HP cap / unexplained heals, ignored damage vs. the host's own hit detection via `observe_damage`, impossible speed / out of world, kill credit only for someone who attacked recently) and answers with a host-side forced death, then a kick after 3 strikes. Any new damage path that skips `take_damage` on a non-authority body must call `observe_damage` there; any new attack path must call `TrustGuard.note_activity`. Gate: C net `trust` (+ every netcase fails on a `TRUST` line from an honest client).
- RPC tags: `@rpc("authority", ...)` = only the node's multiplayer authority may call (server→client replication, or client→its-own-node). `@rpc("any_peer", ...)` = any peer may invoke. `call_local` = also execute on the caller; `call_remote` = remote peers only.
- Map/mode sync flows through `net_set_map(idx, mode_idx, custom_json)`; a joining client is hydrated in `net_client_ready` (host mirrors full world: bots, pickups, GG levels).
- **Preserve these guards everywhere**: `is_multiplayer_authority()` and `multiplayer.multiplayer_peer == null or ...`. Single-player must keep working identically.

## Syntax checking — the full boot is the ONLY reliable check
- `--headless --quit-after 700 res://scenes/main.tscn` (~11s) loads autoloads + the whole game and catches real parse/compile errors. Use this.

## Maps & anti-stuck (v1.13)
- World rect is per map: `main.gd` vars `MAP_W / MAP_H / GROUND_Y / KILL_Y` come from `_map["world"]` (ported maps) or the 4800×2000 defaults. Never hard-code 4800/2000/1900.
- Baseline floor's TOP edge = `GROUND_Y`. Ported maps hide it and kill soldiers below `KILL_Y`.
- Poly `"col"`: 0 solid, 1 bullets-only (layer 2), 2 players-only (layer 3/bit 4), 3 decorative. `"vc"` = per-vertex colours.
- After touching any map data run `python3 tools/map_audit.py` (must print `0 / N maps have problems`). Soak test: `godot --headless --fixed-fps 60 -s tools/stuck_test.gd -- --secs=40 --from=0 --to=26`.
- Re-port classics: `python3 tools/pms_to_map.py --regen <opensoldat/base checkout>` (keeps names + weather; needs numpy/pillow/scipy/shapely). Regen drops `vehicle_spawns` — re-run `tools/place_vehicles.py` after it.
- Rounded corners (#273): `python3 tools/smooth_maps.py [names]` fillets every collision-class outline corner (≤ ~4 px displacement), re-splits the touched collision pieces into convex pieces (untouched pieces stay byte-identical), clips/fills the drawn triangles to match (pieces stay single n-gons, UVs/vertex colours extrapolated from the source triangle) and welds coincident vertex colours. It validates per map (component/hole counts, free-space regions in every stance, bot nav main-region connectivity, entity audit verdicts) and puts offending corners back to sharp. Originals live in `tools/map_src/<map>.json.gz`, so re-runs are deterministic; `--restore` writes them back, `--dry` reports. `--regen` runs it automatically (`--no-smooth` to skip). `movement_course` is excluded (calibrated gaps). Stats per map land in `_source.smooth`. Polys can now be n-gons (`terrain_fx.gd` samples them via their triangulation).
- Bot nav: after ANY map geometry change run `python3 tools/build_nav.py` (graphs are rejected at runtime if poly/collision counts changed). Bot brain = `bot.gd::_think*` (goal) + `_nav_step` (path following).
- Runtime bot nav (#287): maps with no (or a stale) baked graph — editor / Maker / shared / custom maps — get one built in-game by `scripts/nav_builder.gd`, the GDScript port of `build_nav.py` (raster at 4 px cells instead of 2, same node / link / void / ledge-detour / bridge rules; bridge climb limit 790 vs the bake's 740 because the coarser raster measures a little longer). Pure data (reads only the map dict, accepts `[x, y]` or `Vector2` points), so `main._start_runtime_nav()` runs it on a `WorkerThreadPool` task at match start (also on dedicated servers); `_tick_runtime_nav()` adopts it on the main thread via `NavGraph.adopt()` (bots chase directly until then, ~0.3–2 s). Gate: N runs `tools/nav_check.gd -- --runtime` (every classic map rebuilt in-game must pass the same CTF / objective audit as the bake) and F `rtnav` (`tools/runtime_nav_test.gd`: custom copy of a classic + a generated map — graph adopted, no main-thread stall, legs routable, bots travel). `NAV_DEBUG=1` prints raster stats. Keep the two builders in step when changing the rules. Maker hazards (`"hazards"`, runtime builder only — classic maps have none): each rect is rastered solid (padded `HAZARD_PAD_X` 20 px sideways, `HAZARD_PAD_TOP` 20 px up) and its ground rows are removed (`_apply_hazards`), so no node sits on one and links / air bridges go over it. Bot side (`bot.gd`, all no-ops without hazards): `_is_gap` flags a hop over a hazard (`_gap_hazard` → hold the waypoints' altitude, not the void rule's 200 px climb), `_hazard_below()` counts as a void for `falling_to_land` and the void rescue, an airborne bot over a hazard steers to the nearer edge (`_hazard_exit_dir`) and never refuel-waits, bunny-hops skip when `_hazard_ahead`; `main._safe_spawn_near` won't slide a spawn onto one. `rtnav` also runs `maker_hazards` (starter map + 2 spikes + 2 lava: zero nodes on hazards, zero hazard deaths over 25 s; `match_hazards.kill_log` names them) and `maker_vehicles` (a buggy per team: a bot must drive one >= 400 px).
- Soldiers are on physics layer bit 8 and don't collide with each other; anything that must hit soldiers masks bit 8.
- Soak test flags: `--mode=N`, `--trace=<goal label>`, `--trace-name=Blue_Bot_2`, `--log-falls`.

## Gotchas
- GDScript uses TAB indentation — do not convert to spaces.
- Version string is in `project.godot` (`config/version`); bump it for releases together with `export_presets.cfg` (Android `version/name` + `version/code` = MAJOR*10000+MINOR*100+PATCH, Windows `file_version`/`product_version` = X.Y.Z.0) and the top `CHANGELOG.md` heading — the gate checks they agree.
- Release gate: `tools/release_gate.sh` (full, ~20 min: static, boots, nav, MP smokes incl. per-mode `m3 m7 m9` + LAN discovery + a two-client autopilot soak, all 10 modes with the autopilot, rules, feature/editor tests, all-map CTF sweep) or `--quick` (CI). Must end `GATE PASSED`; logs in `build/gate/`. Every Godot launch in the gate starts from default settings/controls (the user's files are backed up and restored), so results don't depend on this machine's saved settings. Piecewise runs (for time-limited shells): `--out build/gateN --only "A B"`, then `--keep` with `--only N`, `--only C --net "..."`, `--only D --modes "..."`, `--only R`, `--only F --ftests "features editor grenade training course" / "weapons" / "fire labels kits sound" / "radio"`, `--only E --sweep 0:24 …75:101`, `--only E`, `--final`. The error regex also fails on engine messages ("Lambda capture … freed", "while flushing queries").
- Host broadcasts from `main.gd` go through `bcast(method, args, local)` (reaches only peers whose Main exists). Dead / disconnected soldiers linger 1.5 s as an inert husk (`player._become_husk`) so in-flight packets still find the node.
- Host → client RPCs from bots/projectiles go only to acked peers (`ready_peer_ids()`, `_bcast`, `_net_send`); a plain `rpc()` reaches peers still loading and spams "Node not found".
- MP respawns are scheduled by `main._schedule_peer_respawn`; objective events go through `_objective_event` (never the `kill` signal).
- Path has a space (`soldat reborn/game`) — always quote it in shell commands.
- Remote bodies are smoothed: set replica positions through `net_apply_pos(pos, vel)` (player.gd / bot.gd), not `position =`. Nav JSON `air` = mid-air waypoints; never use them as patrol/roam targets.
- Builds: `tools/build_release.sh [win|android|all]` → build/SoldatReborn.exe + signed .apk (stub SDK + uber-apk-signer; keystore lives in ../keys, outside the repo).
- After changing map JSON (regen / overrides) also re-run `python3 tools/build_nav.py` and `python3 tools/make_thumbs.py` (menu previews in assets/map_thumbs).
- GitHub tracking: every bug / feature gets an issue first (bug report / feature templates, `bug`|`enhancement` + `area: …` labels), the fixing commit says `Fixes #N`, the CHANGELOG line cites `(#N)`, releases carry the exe + apk (`python tools/github/sync.py release`).
